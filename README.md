# article Contribute

Nous accueillons favorablement les contributions de notre communauté ainsi que des employés Adobes de l&#39;extérieur des équipes de documentation.

## Code de conduite Adobe Open Source

Ce projet a adopté le [Code de conduite Open Source de l&#39;Adobe](code-of-conduct.md) ou le [.NET Foundation Code of Conduct](https://dotnetfoundation.org/code-of-conduct). Pour plus d&#39;informations, consultez l&#39;article [Contributing](contributing.md).

## Comment contribuer au contenu Adobe

**Si vous n&#39;êtes pas un employé Adobe**, vous pouvez envoyer une contribution de communauté externe. Les contributions communautaires sont importées dans nos systèmes internes et sont éditées et fusionnées dans le référentiel public. Le référentiel public est ensuite synchronisé avec les dernières modifications et fusionné dans le référentiel privé.

**Si vous êtes un employé Adobe**, vous pouvez contribuer directement au [référentiel GitHub Adobe](https://git.corp.adobe.com/AdobeDocs/) privé. Pour plus d’informations, voir le Guide de création Adobe Experience League pour les employés Adobes.

## Contributeurs externes

### Modifications mineures

Si vous apportez une mise à jour mineure :

1. Accédez à la rubrique à modifier.
1. Dans la section « Ce contenu a-t-il été utile ? » Une bannière qui apparaît en bas de la fenêtre de votre navigateur, cliquez sur **Options de commentaires détaillés**.
1. Cliquez sur **Suggérer une modification** et envoyez une demande d&#39;extraction (PR) avec vos modifications dans l&#39;interface utilisateur GitHub.

   Pour plus d&#39;informations, consultez le [guide du contributeur Adobe Docs](https://experienceleague.adobe.com/docs/contributor/contributor-guide/introduction.html) général.

Les corrections ou clarifications mineures que vous soumettez pour la documentation et les exemples de code dans ce référentiel sont couvertes par les conditions d’utilisation d’Adobe.

### Modifications majeures ou nouveaux sujets de la communauté

Si vous faites partie de la communauté d&#39;Adobe et que vous souhaitez créer une nouvelle rubrique ou soumettre des modifications majeures, utilisez l&#39;onglet **Problèmes** dans le référentiel Git applicable pour soumettre un problème afin de commencer une conversation avec l&#39;équipe de documentation. Une fois le plan convenu, vous travaillerez avec un rédacteur d’Adobe pour publier vos révisions.

**REMARQUE :** si vous soumettez une demande pull avec des modifications importantes de la documentation et des exemples de code, un message s&#39;affiche dans la demande pull vous demandant de soumettre un accord de licence de contribution (CLA) en ligne. Vous devez remplir le formulaire en ligne avant que nous puissions examiner votre demande d’extraction.

### Outils

Les contributeurs de la communauté peuvent utiliser l’interface utilisateur GitHub pour effectuer des modifications de base ou créer un référentiel pour apporter des contributions majeures.

Consultez le [Guide du contributeur Adobe Docs](https://experienceleague.adobe.com/docs/contributor/contributor-guide/introduction.html) pour plus de détails.

## Contributeurs internes

Si vous êtes rédacteur technique, gestionnaire de programme ou développeur au sein de l&#39;équipe produit d&#39;une solution Adobe Experience Cloud et qu&#39;il vous appartient de contribuer à ou de rédiger des articles techniques, utilisez le [référentiel privé](https://git.corp.adobe.com/AdobeDocs).

## Mise en forme de la rubrique

Tous les articles de ce référentiel utilisent un Markdown parfumé GitHub. Si vous ne connaissez pas Markdown, reportez-vous aux sections suivantes :

* [Principes de base de Markdown](https://help.github.com/articles/getting-started-with-writing-and-formatting-on-github/)
* [Aide-mémoire Markdown imprimable](https://guides.github.com/pdfs/markdown-cheatsheet-online.pdf)

## Étiquettes

Dans le référentiel public, des étiquettes automatisées sont affectées aux demandes d’extraction pour nous aider à gérer le workflow des demandes d’extraction et pour vous aider à savoir ce qui se passe avec votre demande d’extraction :

* **Modification envoyée à l&#39;auteur** : l&#39;auteur a été informé de la demande d&#39;extraction en attente.
* **prêt à fusionner** : prêt pour révision par notre équipe d&#39;examen des demandes d&#39;extraction.
